# AGENTS.md — working on the Rune repository

Instructions for AI coding agents (Codex, Grok Build, Cursor, Copilot, Gemini CLI, Cline, Amp, Kiro …) working **on this repo**.
Claude Code reads `CLAUDE.md`, which holds the same rules plus the skill-routing table.

Rune is a 67-skill engineering mesh for AI coding agents: 5 layers, 248 connections, 46 signals, compiled to 16 platforms.
Philosophy: **less skills, deeper connections.**

## Setup and commands

Node.js ≥ 18, no build step for the source. Install dev deps with `npm install`.

| Task | Command |
|------|---------|
| Full CI gate (run before every commit) | `npm run ci` — Biome lint + all tests + `rune doctor` + version/number sync + skill-index check |
| Tests only | `npm test` (`node --test`, ~1,800 tests) |
| Lint / auto-fix | `npm run lint` / `npm run lint:fix` |
| Number + version drift check | `node scripts/version-sync-check.js` |
| Skill description budget | `npm run description-check` (≤ 500 chars each, ≤ 20,000 total, no ALWAYS/ANY shouting) |
| Validate the Grok plugin + hooks | `grok plugin validate .` · `grok inspect --json` (`hookLoadErrors` must be empty) |
| Regenerate `skill-index.json` | `node scripts/build-skill-index.js` |
| Compile for a platform | `node compiler/bin/rune.js build --platform <id> --output <dir>` |
| Validate a compiled output | `node compiler/bin/rune.js doctor --output <dir>` |
| Validate the Claude plugin | `claude plugin validate .` |
| Validate the Gemini extension | `gemini extensions validate .` |
| Bump version everywhere | `node scripts/bump-version.js <x.y.z> --title "<wave name>"` |
| Cut a release (bump + CHANGELOG `[Unreleased]` → version + ci + commit on `release/v<x.y.z>`) | `npm run release -- <x.y.z> [--title "<wave>"] [--pr]` |
| Publish after the release PR merged (checks, warning-free dry run, `--auth-type=web`, tag + GH release) | `npm run release:publish` (`-- --dry-run` to stop before publishing) |

Platform ids: `claude codex cursor windsurf antigravity opencode openclaw generic aider copilot gemini qoder qwen grok cline agents`.

## Layout

```
skills/<name>/SKILL.md     core skills — the single source of truth (+ references/, scripts/)
extensions/<pack>/PACK.md  L4 free packs
agents/  commands/  hooks/ Claude-format subagents, slash commands, runtime hooks
compiler/                  SKILL.md → IR → platform output (adapters/, transforms/, bin/rune.js)
scripts/                   CI checks, version tooling, hook helpers (+ __tests__/)
docs/                      architecture, guides, GitHub Pages site (docs/index.html)
plugin.json                Agent Plugins 1.0 manifest
.claude-plugin/ .cursor-plugin/ .grok-plugin/ .codex-plugin/ gemini-extension.json   per-agent manifests
```

## Rules that CI enforces

- **Skills follow the Agent Skills spec.** `name` = directory name, lowercase kebab-case, ≤ 64 chars; `description` ≤ 1024 chars; `metadata` values are strings. Use `docs/SKILL-TEMPLATE.md`.
- **Layer rules.** L1 calls L2/L3. L2 calls L2/L3. L3 calls nothing except documented L3→L3 coordination. `team` (L1) may call other L1s. Every cross-reference (`rune:<name>`) must resolve — `rune doctor` fails on dangling refs.
- **Signals.** Every emitted signal needs a listener (or a documented reason); `scripts/validate-signals.js` runs in CI.
- **Numbers are checked.** Skill, signal, connection and platform counts in README, ROADMAP, manifests, docs and this file are compared with the live mesh. If you add a skill or signal, update the counts or CI fails and tells you where.
- **Versions are checked.** All manifests (`package.json`, `plugin.json`, `.claude-plugin/*`, `.cursor-plugin/plugin.json`, `.grok-plugin/marketplace.json`, `gemini-extension.json`, `.codex-plugin/plugin.json`) carry the same version. Use `bump-version.js`; don't edit versions by hand.
- **Agent frontmatter** in `agents/*.md` uses only `name`, `description`, `model` (Gemini CLI rejects unknown keys).

## Conventions

- Conventional commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`, `test:`.
- Write the test first for compiler, script and hook changes (`compiler/__tests__/`, `scripts/__tests__/`).
- New platform adapter: add `compiler/adapters/<id>.js` (directory-per-skill runtimes can use `agent-skills-base.js`), register it in `adapters/index.js`, add it to `adapters.test.js` and `scripts-bundling.test.js`, and update the platform count.
- Keep the Free compiler tier-agnostic. Pro/Business packs live in separate private repos and stack via `--tier`.
- Hooks are CommonJS (`hooks/**/index.cjs`), must exit 0 on any error, and print a JSON envelope (Codex discards anything else).
- `CHANGELOG.md` gets a user-facing entry for every release — write it under `## [Unreleased]`; `npm run release` renames the heading.

## Don't

- Don't add isolated skills; every new skill must be wired into an existing orchestrator or hub.
- Don't commit compiled output (`.cursor/`, `.grok/`, `.agents/` …) — it is generated by users' `rune init`.
- Don't add telemetry or network calls to hooks.
